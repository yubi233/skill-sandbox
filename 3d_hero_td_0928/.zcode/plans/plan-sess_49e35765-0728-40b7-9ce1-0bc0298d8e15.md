## 目标与原则

以 `3d_survivors_like_0922`（Vite + TS + core/render 分层 + 无头验收）为参照，把本项目从「IIFE 全局单例 + 脚本拼接」迁移到同代工程架构。三条铁律：

1. **行为保持**：玩法数值、美术、文案、操作手感不变；每阶段结束游戏必须可玩、`npm run verify` 必须全绿。
2. **离线单文件保留**：构建产物仍是根目录 `legion-breaker.html`（内联 Babylon 与贴图，双击可玩），这是现有 README 契约，参考项目没有这点，要保留。
3. **现有强测试全部保留**：资源基线、构建幂等、无尽循环全程模拟、首次火球门控等 59 项，迁移到新测试体系后语义不变。

## 目标结构

```
package.json / tsconfig.json(strict) / vite.config.ts
index.html                     ← 由 page.html.src 改造（CSS 内联 + module 入口）
src/
  core/                        ← 纯逻辑：禁止 import Babylon/DOM/window（grep 门禁测试强制）
    config.ts rng.ts events.ts
    rules/{waves,delve,stats,combat}.ts
    director.ts                ← 状态机+经济，产出事件与意图，不直接调 Units
  render/                      ← Babylon + DOM
    main.ts                    ← 引擎、固定步长主循环、事件排水与分发
    scene.ts mage.ts target_ring.ts
    entities/{units,rigs,projectiles,hp_bar}.ts
    skills.ts particles.ts ui.ts input.ts
  generated/textures.ts        ← 构建前由 assets/*.png 生成（替代 __TEX_PNG 注入）
tools/headless_sim.ts          ← 无头验收：参考 AI 完整下探 + 性能分位
tests/*.test.ts                ← node:test + tsx，直连模块，无 VM 沙盒
dev/ → 迁移验证完成后删除（git 历史保留）
```

## 关键决策

- **Babylon 用 npm `@babylonjs/core` 锁 7.54.3**（与现 vendor 同版本，避免视觉回归；不跟参考项目升 9）。ES 按需引入，单文件体积预期持平或更小。
- **单文件产物**：`vite-plugin-singlefile` + Vite input 命名为 `legion-breaker.html`，`npm run build` 后复制到项目根目录，预览服务器的现有 URL 不变。`npm run dev` 额外获得 HMR 热更新开发模式。
- **贴图内联**：构建前脚本把 `assets/*.png` 生成为 `src/generated/textures.ts`，particles 解码管线不变。
- **测试**：`node:test` + `tsx` 直连 `src/core`（不再有 VM 沙盒和三份模块顺序清单）；资源基线类测试继续用 NullEngine（npm 包在 node 下可用）。

## 分阶段步骤（每阶段有硬门禁）

**阶段 0 · 基线**：提交当前全部改动作为迁移前基线（执行时向你确认提交信息）；记录 verify 与构建产物基线。

**阶段 1 · 工具脚手架**：package.json/tsconfig/vite.config/贴图生成脚本/index.html 改造；先用「临时包裹旧 JS」的方式打通 Vite 构建出等价单文件。门禁：产物在浏览器打开与旧版一致（数值探针核对）。

**阶段 2 · TS 模块转换**（工作量主体）：按依赖叶到根逐文件转 TS strict：particles → config → core(拆 scene/mage/target_ring) → entities(拆 units/rigs/projectiles/hp_bar) → skills → director → ui → main(拆 input)。同时消除已知债：
- 三份模块顺序清单 → 天然 import 顺序；删除 `typeof DIRECTOR` 类加载守卫；
- 字符串键分发（rig 的 else=hunter、CAST_CLASSES、allyStats if/else）→ 配置表显式注册 + `validate()` 启动期大声报错；
- 魔法数进 config（AGGRO、远段阈值、弹池上限、路线几何单源、相机/泛光参数）；
- 热路径 `JSON.stringify` 缓存键、fxEmitters 不释放、FX.time 双写者等性能卫生问题。
门禁：typecheck 0 错误；59 项测试迁移后全绿；浏览器冒烟。

**阶段 3 · 结构模式移植**（参考项目精髓）：
- `events.ts` 类型化事件队列（带上限与丢弃计数），core→render 唯一通道；UI/FX 改为排水消费；
- director 变纯状态机+意图（spawn/clear 由 main 执行），**修复 entities↔director 双向重入**（败北清场移到 tick 后执行，中帧守卫降级为保险）；
- 固定步长 60Hz 累加器 + 整数 tick 计时 + 后台补帧，替代渲染 dt 驱动；
- mulberry32 种子随机 + `?seed=` URL + 领域种子（战斗/表现分离）；
- `rules/stats.ts` 统一数值源：法术实际效果、阵营加成、营地预览文案全部读同一份函数，新增「预览与实际一致」测试（消灭最大痛点：UI 撒谎）；
- `rules/combat.ts` 收编 main.js 里的空格目标策略与 tryCast 校验顺序，配纯逻辑测试。
门禁：`src/core` grep 门禁 0 违例；新增模式测试全绿。

**阶段 4 · 无头验收测试**：`tools/headless_sim.ts`——参考 AI（火球打最密敌群、低血撤退、回营按优先级购买）跑完整下探；门禁：AI 能推进到约定波次、赚够升级费、tick p95 达标、零 console 错误；附 200+ 敌人压力模式。接入 `npm run verify`。

**阶段 5 · 清理与文档**：删除 dev/ 旧管线，README 架构章节重写（新命令、新结构、分层契约），更新项目记忆。

## 明确不做

- 不移植参考项目的 VAT 骨骼群、体素地图生成器、monkey-patch 集成、模块作用域单例大杂烩；
- 不改任何玩法数值/美术/文案（`?seed=` 只约束随机，不改平衡）；
- 不动你工作区里与本游戏无关的文件。

## 风险与对策

- **体量**：全量 4,650 行转 TS strict，阶段 2 占大头；按文件推进、每个文件过 typecheck，任何时刻可暂停不留半成品。
- **视觉回归**：贴图/材质/管线参数不变 + Babylon 锁同版本；每阶段用数值探针（投影、坐标、像素统计）+ 你的人工确认双保险。
- **测试写直改字段**（`DIRECTOR.state=` 等约 15 处）：随迁移改为显式测试助手，语义不变。

## 验收标准

`npm run verify`（typecheck + 全部测试 + 无头模拟 + 构建）全绿；根目录单文件 HTML 离线可玩且与迁移前玩法一致；`src/core` 零 Babylon/DOM 依赖；你在浏览器里的完整循环（首战→回营→购升级→再下探→头目波）人工验证通过。
